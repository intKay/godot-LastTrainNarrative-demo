---
description: 评审 data/ 中所有面向玩家的叙事文本——短、冷、准、忌越界
---

先读取 docs/101 §5（系统待处理项文本）、docs/102 §14-15（AI 约束与幻觉控制）。

然后加载 `data/calibration_questions.json`、`data/story_nodes.json`、`data/interactables.json`、`data/endings.json`，提取所有面向玩家的文本（visible_text、options.text、feedback_text、body、investigated_text、echo_text 等）。

逐条评审：

## 文本风格
1. **短**：每条文本能否再精简？有无啰嗦重复？
2. **冷**：是否符合"冷淡系统 UI"口吻？有无教程腔（"请点击……"）、抒情腔、散文腔？
3. **准**：每条文本是否传递明确信息？有无模糊堆砌？
4. **有信息量**：每条文本是否至少承担"反馈选择 / 提供新信息 / 暗示状态变化"之一？

## 系统口吻一致性
5. 系统解释文本是否用"系统推测 / 系统判断"而非直接写玩家心理（"你很害怕"）？
6. 公告屏文本是否保持记录/回刷/写入感？
7. 设备反馈文本是否以"系统记录"为中心？

## 禁词检查
8. 是否出现禁止词汇：列车员 / 乘客 / 怪物 / 真实城市 / 车厢内部 / 站外场景 / 隐藏房间 / 真实逃脱路线 / 第四结局 / NPC？
9. 是否暗示不存在的内容（新角色、新物件、新路线）？

## 长度限制
10. 选项文本是否 ≤ 24 个中文字符（不含 A/B/C/D 前缀）？
11. AI/系统解释文本是否 1-3 行？

## 输出格式

```
文本评审报告

逐条评分（通过 / 需修改 / 需重写）：
  [文件:行] 原文 → 问题描述 → 建议改写

禁词违规：
  [文件] 位置 / 违规词

统计数据：
  通过 xx 条 / 需修改 xx 条 / 需重写 xx 条
```
