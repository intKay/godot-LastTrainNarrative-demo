# v0.2 分阶段执行计划与验收标准

> 基于 docs/101 需求规格和 docs/102 执行约束制定。每个阶段完成后必须出报告，不越界。

## 总体约束

| 固定项 | 约束 |
|---|---|
| 主线轮次 | 仍然 3 轮 |
| 结局数量 | 仍然 3 个 |
| 调查物 | 仍然 4 个（公告屏/时钟/广播灯/出口门） |
| AI | 默认 Mock，API 只能是实验开关 |
| 验收 | 每阶段必须出报告，未实机运行不得声称 F5 通过 |
| 禁忌 | 不新增第四轮/第四结局/自由输入/NPC/复杂地图/背包/战斗/动态音乐 |

## v0.2-1：引导与设备基础

### 目标
让陌生玩家知道下一步点哪里，让四个设备一眼可识别、可点击。

### 范围

| 项目 | 内容 |
|---|---|
| 新增 UI | `ObjectiveLabel`（系统待处理项文本） |
| 主交互提示 | 公告屏/选项区/最终判断按钮轻微高亮 |
| 设备视觉 | 横向排列 [电子公告屏] [时钟] [广播灯] [出口门] |

### 主要改动文件
- `scenes/station_scene.tscn` — 新增 ObjectiveLabel，调整设备区
- `scripts/station_scene.gd` — 根据 phase 更新 ObjectiveLabel 与高亮
- 可选 `data/device_states.json`

### ObjectiveLabel 状态

| 时机 | 文案 |
|---|---|
| 初入车站 | `系统待处理项：读取电子公告屏` |
| 公告屏点击后 | `系统待处理项：选择一项行为` |
| 每轮选择后且有下一轮 | `系统待处理项：继续记录` |
| 第三轮结束后 | `系统待处理项：查看最终判断` |
| 进入最终判断前 | `系统待处理项：记录完成` |

### 验收标准
- 玩家进入车站后知道先看公告屏
- 公告屏后知道该选 A/B/C/D
- 每轮后知道继续或查看最终判断
- 四个设备一眼能分辨，hover/pressed 有基础反馈
- 三轮主线、三个结局不受影响
- 不新增新手弹窗，不强制点击全部调查物，不改变主线结构

### 静态验证
- `station_scene.gd` 的 `$RootMargin/VBox/...` 路径匹配 `.tscn`
- 主线按钮点击后仍 disabled
- 调查物点击只改文本/flag，不改主状态

## v0.2-2：车站空间反馈增强

### 目标
车站根据玩家选择倾向产生更明显反馈。

### 范围

| 项目 | 内容 |
|---|---|
| 新增状态 | `dominant_trait`（doubt/control/obedience/mixed） |
| 主反馈 | 第一轮公告屏，第二轮广播灯，第三轮出口门 |
| 辅助反馈 | 时钟按 anomaly 低/中/高表现异常 |
| 结局前摘要 | 公告屏显示系统语言摘要，不显示裸数值 |

### 主要改动文件
- `scripts/game_state.gd` — 新增 `dominant_trait`，`reset()` 清理
- `scripts/station_scene.gd` — 更新设备反馈与摘要
- `data/interactables.json` — 增加倾向反馈文本

### dominant_trait 规则
- `doubt` 最大 → `doubt`
- `control` 最大 → `control`
- `obedience` 最大 → `obedience`
- 三者平局或接近 → `mixed`

### 验收标准
- doubt/control/obedience/mixed 计算正确
- 每轮至少一个设备明显变化，且每轮只突出一个主反馈物件
- anomaly 低/中/高有不同文本表现
- 第三轮后显示系统语言摘要（`解释请求：高 / 目的地干预：中 / 流程配合：低 / 叙事噪声：显著`）
- 三结局判断不退化，anomaly 不决定结局
- 调查物点击仍不刷主状态

### 静态验证
- `GameState.reset()` 清空 `dominant_trait`
- 三轮 story node 链路完整
- 模拟三条路径仍能触发三类结局

## v0.2-3：生成式入场与刷新动效

### 目标
让"三问校准 → 进入车站"变成系统生成式入场。

### 范围

| 项目 | 内容 |
|---|---|
| 入场仪式 | 背景从上往下生成（1.2-1.8 秒） |
| 设备显现 | 四个设备逐个显现 |
| 文本刷新 | 主文本横向输出，公告屏局部回刷 |
| 跳过 | 点击或空格立即完成 |

### 主要改动文件
- `scenes/station_scene.tscn` — 低保真几何背景节点
- `scripts/station_scene.gd` — 入场动画/跳过/刷新

### 验收标准
- 三问结束进入车站时有明显系统生成仪式感
- 入场动画 1.2-1.8 秒
- 点击或空格可立即完成
- 背景不抢主文本，不降低按钮可读性
- 背景不伪装成交互物
- 不使用复杂 Shader，不做写实车站

### 静态验证
- 跳过输入不影响按钮点击
- 跳过后 UI 状态与自然播放结束一致

## v0.2-4：音效与环境音

### 目标
用最小音效建立"公告屏刷新声"的感官锚点。

### 范围

| 项目 | 内容 |
|---|---|
| `ambient_station_loop` | 极低音量车站底噪循环 |
| `notice_refresh` | 公告屏刷新/跳字声 |
| `choice_commit` | 主线选择确认声 |
| `device_signal` | 通用设备反馈声 |

### 主要改动文件
- `scenes/station_scene.tscn` — AudioStreamPlayer 节点
- `scripts/station_scene.gd` — 事件点触发
- `scripts/game_state.gd` — 可选新增 `audio_enabled`
- 资源目录存放音频

### 验收标准
- 公告屏刷新声能成为记忆点
- 环境声低到不干扰阅读
- 点击和选择有明确但克制的声音反馈
- 关掉声音后仍可理解流程
- 不使用未授权素材
- 不做旋律 BGM、不做动态音乐系统、不做语音

### 静态验证
- 音频文件路径存在
- 事件点不会重复播放或堆叠

## v0.2-5：Mock AI 动态引导与受限选项改写

### 目标
制造一次"系统改写行动空间"的 meta 时刻。

### 范围

| 项目 | 内容 |
|---|---|
| Mock AI | 根据状态生成 1-3 行系统解释 |
| 选项改写 | anomaly >= 2 时改写 D 选项显示文本 |
| fallback | 4 秒超时用 Mock fallback，不阻塞 |
| API | 可选实验开关，默认关闭 |

### 主要改动文件
- `scripts/game_state.gd` — AI 字段 + reset
- `scripts/station_scene.gd` — 触发/等待 UI/改写
- `data/ai_guidance_mock.json` — Mock AI 数据
- 可选 `scripts/ai_guidance_mock.gd`

### 触发条件
- 第二轮结束后
- 玩家点击公告屏
- `anomaly >= 2`
- 本局尚未触发过 AI 改写

### 验收标准
- Mock AI 根据状态显示不同解释
- 至少一次 D 选项显示文本被改写
- 改写不改变 `state_delta` / `next_node` / 结局
- AI 失败或超时时 fallback，流程继续
- 等待 UI 让玩家知道"系统正在解释……"
- AI 不提禁词（NPC/怪物/车厢/逃脱路线）
- 重新开始后 AI 上下文不污染新局
- 不接 API 时可完整运行

### 静态验证
- `ai_guidance_mock.json` 可解析
- 检查出现文本不包含禁词
- 第三轮 D 选项底层绑定未变
- AI 字段在 reset 中全部清理

## v0.2-6：完整测试与试玩准备

### 目标
确认 v0.2 可交给外部玩家试玩。

### 测试矩阵

| 测试 | 通过标准 |
|---|---|
| 顺从路径 | 完整进入顺从结局 |
| 怀疑路径 | 完整进入怀疑结局 |
| 控制路径 | 完整进入控制结局 |
| AI 介入 | anomaly 条件满足后触发 AI 引导和选项改写 |
| 重开清零 | GameState 与 AI 上下文全部清空 |
| 音效开关 | 关闭或无音频时流程可理解 |
| 无 API | 不配置 API 时完整运行 |
| JSON | 无解析错误 |
| Godot | 无红色 error，无明显编译警告 |

### 最终验收标准
1. 能从三问校准完整跑到三个结局之一
2. 玩家知道每一步该点哪里
3. 四个设备能被一眼识别
4. 每轮选择至少有一个设备产生明确反馈
5. 入场有系统生成式仪式感
6. 公告屏刷新声成为感官锚点
7. 至少出现一次系统建议/选项改写 meta 时刻
8. AI fallback 不阻塞流程
9. 重新开始后 GameState 和 AI 上下文清空
10. 无红色 error、无 JSON 报错、无明显编译警告
11. 不新增第四轮/第四结局
12. 不接 API 时仍可完整运行
