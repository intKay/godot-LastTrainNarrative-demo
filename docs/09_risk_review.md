# 《叙事校准程序 / 末班车站》v0.1 风险审计

## 最高风险：文案平庸

风险描述：

本项目的核心体验高度依赖文本。状态机、UI 变化和异常机制只是骨架。真正让玩家感到“被系统看见”的，是短文本的节奏、暗示和反馈。如果文本平庸，机制再完整也会显得空。

控制方案：

1. 每段主文本控制在 1～4 行
2. 每段调查文本必须提供新信息
3. 避免大段解释世界观
4. 避免过度文艺化
5. 优先使用冷淡、系统化、具体的描述
6. 每句话承担功能：推进、反馈、暗示、误导、揭示

## 选择无意义风险

风险描述：

如果玩家发现不同选择只是换一句话，剧情很快回到同一路径，会觉得被欺骗。

控制方案：

1. 每个选项必须有 state_delta
2. 每个选项至少改变一个世界元素、状态或 flag

## meta 俗套风险

风险描述：

“其实你一直被测试”容易显得平庸或被提前猜到。

控制方案：

1. 前期不直接解释
2. 中期只泄露系统痕迹
3. 后期用冷淡 UI 语言暴露真相
4. 不用大段说教
5. 重点不是“反转”，而是“系统如何描述玩家选择”

## 异常疲劳风险

风险描述：

每轮都出现新异常，会让玩家麻木或烦躁。

控制方案：

1. 异常必须升级，而不是堆叠
2. 每轮只有一个主异常
3. 所有异常都围绕“系统记录玩家选择”
4. 不加入无关恐怖元素

## UI 信息过载风险

风险描述：

公告牌、时钟、广播灯、出口门同时变化，玩家不知道看哪里。

控制方案：

1. 每轮突出一个主元素
2. 其他元素只做轻微辅助变化
3. 调查文本保持短
4. 选项数量控制在 3～4 个

## 范围膨胀风险

风险描述：

车站、测试系统、meta、AI、音效、美术、自由度都想做，导致第一版无法完成。

控制方案：

1. v0.1 不接真实 AI
2. 不做自由输入
3. 不做移动
4. 不做背包支线
5. 不做多 NPC
6. 不做复杂谜题
7. 先做 1 分钟切片

## AI 接入过早风险

风险描述：

过早接入 DeepSeek / OpenAI 等模型，会导致时间花在 prompt、延迟、JSON 校验和 API 问题上，而不是核心玩法。

控制方案：

1. v0.1 使用 MockAI
2. 先验证玩法闭环
3. 后续 AI 只负责润色文本和局部变化
4. AI 不决定主线结构

## Godot 学习卡住风险

风险描述：

新手如果跳过基础教程直接做项目，会卡在节点、信号、UI 布局、JSON 读取等基础问题上。

控制方案：

1. 先做阶段 0 最小练习
2. 只学本项目需要的 Godot 内容
3. 不学无关系统
4. 用低保真 UI 开发，不先追求美术

## v0.1 完整原型新增风险

### 内容膨胀风险

风险描述：

从 1 分钟切片扩展到 3～5 分钟 v0.1 原型，内容需求增长 2～3 倍，容易超出可控范围。

控制方案：

1. 只做 v0.1 必需的 8 项功能（三轮/三问/四调查物/三结局）
2. 每个超出建议的扩展必须审计：是否服务于核心体验
3. 不做 5 轮、不做完整商业版、不做联网功能

### JSON 复杂度上升风险

风险描述：

JSON 文件从 1 轮数据扩展到 3 轮 + 4 调查物 + 结尾，结构嵌套变深，容易出错。

控制方案：

1. 保持 JSON 单层嵌套，不超过 3 层
2. 每次扩展 JSON 后运行完整验收
3. 严格遵循 `docs/07_content_data_spec.md` 的命名规范

### 多轮选择反馈变弱风险

风险描述：

第二轮和第三轮如果反馈与第一轮相似，玩家会觉得选择只是换行文本，无实际变化。

控制方案：

1. 每轮突出一个主异常，异常围绕"系统记录玩家选择"升级
2. 第二轮引入系统异常，第三轮引入系统暴露
3. 车站元素（广播灯/公告屏）的反馈必须每轮不同
4. `anomaly` 值影响系统的异常程度

### 结局判断生硬风险

风险描述：

如果结局只是比较三个状态值大小，玩家会觉得被统计而非被理解。

控制方案：

1. 结局文本只描述系统如何解读玩家的选择模式，不说教
2. 结局不要突然解释"你在被测试"
3. 三种结局文本设计：系统化的冷淡反馈
4. 拒绝所有、顺从等极端情况的空结局可后续补充

### 调查物过多信息过载风险

风险描述：

四个调查物同时出现在车站中，玩家不知道点哪个，或每轮都点完觉得重复。

控制方案：

1. 每轮只突出一个主调查物（公告屏始终为主，因为承载残影）
2. 其他调查物只做轻微辅助变化
3. 调查文本每轮不超过 3 行
4. 不要要求玩家必须点击所有调查物才能通关

## 负反馈审计原则

每新增一个机制，都要问：

1. 实现成本是否过高？
2. 是否增强主玩法？
3. 玩家是否能理解？
4. 是否会造成等待、困惑或被欺骗感？
5. 是否会稀释“系统观察玩家选择”的主轴？
