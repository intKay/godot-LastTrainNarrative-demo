# 《叙事校准程序 / 末班车站》v0.3 AI 原生方向草案

## 1. 文档定位

本文件不是当前立即执行文档，而是 v0.3 方向草案。

v0.2 的目标是把 v0.1 打磨成可外部试玩增强版，并建立一次可感知的 AI 式介入。

v0.3 的目标是在不显著扩大总工作量的前提下，把 v0.2 的"AI 原生雏形"推进为更稳定、更可感知、更可复用的"受限 AI 互动叙事系统"。

## 2. v0.3 一句话目标

v0.3 的目标是：

```text
让 AI 不只是改写一句提示，而是成为"受限叙事系统"的一部分：
它能读取玩家历史，生成系统解释、候选行动文本、设备状态描述，并在本地规则约束下参与玩家下一步体验。
```

但 v0.3 仍然不做完全自由输入和完全 AI 剧情生成。

## 3. v0.3 与 v0.2 的区别

v0.2：

```text
AI / Mock AI 在某个关键时刻解释玩家行为；
系统可改写一个选项；
API 是可选实验；
默认仍以 Mock + JSON 为主。
```

v0.3：

```text
AI 介入从"单点事件"升级为"受限系统"；
AI 可以在每轮生成候选表达；
AI 可以生成设备状态描述；
AI 可以生成本轮选项文本变体；
本地规则负责校验、绑定和 fallback；
AI 仍不决定结局、状态数值和主线结构。
```

## 4. v0.3 设计原则

v0.3 继续遵守：

```text
不做第四轮；
不做第四结局；
不做多 NPC；
不做复杂地图；
不做自由长文本输入；
不让 AI 决定核心状态；
不让 AI 决定结局；
不让 AI 自由新增世界元素。
```

v0.3 的重点是：

```text
加深 AI 原生长板；
保持 Godot 项目可控；
保持三轮结构；
让 AI 输出被结构化规则吸收；
让玩家更明显感到系统在"理解并重写"自己的行动空间。
```

## 5. v0.3 推荐需求列表

v0.3 建议包含 5 个核心需求：

```text
需求 1：AI Context Packet 标准化
需求 2：AI 选项文本生成，但意图槽固定
需求 3：AI 设备状态描述生成，但物件固定
需求 4：受限自由询问 / 公告屏问句实验
需求 5：AI 日志、调试与失败回放系统
```

这 5 个需求的总工作量应控制在与 v0.1 / v0.2 接近的水平。

---

# 6. v0.3 需求 1：AI Context Packet 标准化

## 6.1 目标

建立统一的 AI 请求上下文包，让所有 AI 调用都基于同一套数据。

v0.2 可能只有一次 AI 介入，v0.3 需要多处 AI 介入，因此必须标准化上下文。

## 6.2 上下文包内容

每次 AI 请求都包含：

```json
{
  "session_id": "run_001",
  "request_id": "round_2_notice_guidance",
  "mode": "guidance | option_text | device_state | free_question",
  "current_node_id": "station_round_2",
  "phase": "FINISHED",
  "choice_history": [],
  "clicked_interactables": [],
  "last_choice_label": "",
  "dominant_trait": "control",
  "doubt": 1,
  "control": 2,
  "obedience": 0,
  "anomaly": 2,
  "initial_world_hint": "door",
  "available_objects": [
    "notice_board",
    "clock",
    "broadcast_light",
    "exit_gate"
  ],
  "allowed_intents": [
    "doubt",
    "control",
    "obedience",
    "observe"
  ],
  "forbidden_content": [],
  "output_schema": {}
}
```

## 6.3 要求

```text
每次请求显式发送完整状态；
不依赖模型记忆；
重新开始必须刷新 session_id；
AI 输出必须带 request_id；
日志中保存 request_id 方便回放。
```

## 6.4 价值

这是 v0.3 的基础设施。它本身不直接提升玩家体验，但能支撑后续 AI 选项、设备状态、自由询问等能力。

# 7. v0.3 需求 2：AI 选项文本生成，但意图槽固定

## 7.1 目标

让每一轮的 A/B/C/D 选项更像是系统根据玩家历史重新生成的，而不是完全预制。

但底层结构仍然固定。

## 7.2 固定意图槽

每轮选项仍然保持 4 个槽位：

```text
A：doubt / 追问 / 要求解释
B：control / 改写 / 干预目的地
C：obedience / 等待 / 配合流程
D：observe 或 mixed / 沉默 / 观察 / 特殊建议
```

AI 只能生成显示文本。

AI 不能改变：

```text
slot；
intent；
state_delta；
next_node；
结局规则；
选项数量。
```

## 7.3 示例

基础结构：

```json
{
  "slot": "A",
  "intent": "doubt",
  "state_delta": {
    "doubt": 1,
    "anomaly": 1
  }
}
```

AI 生成文本：

```text
要求广播复述第一次校准选择
```

最终显示：

```text
A. 要求广播复述第一次校准选择
```

## 7.4 价值

玩家会感觉：

```text
选项不是固定菜单；
系统正在根据我刚才的行为重新生成行动语言。
```

这比 v0.2 的"只改写一次选项"更进一步。

## 7.5 风险

```text
AI 生成选项太长；
AI 生成选项不符合意图；
AI 暗示不存在的路线；
AI 让玩家以为有新结局；
AI 语气不统一。
```

## 7.6 控制

```text
每个选项不超过 24 个中文字符；
必须包含当前 intent 对应行为；
禁止出现未授权对象；
本地校验失败则使用 JSON fallback；
每轮最多允许 AI 生成一次完整选项组。
```

# 8. v0.3 需求 3：AI 设备状态描述生成，但物件固定

## 8.1 目标

让公告屏、时钟、广播灯、出口门的调查文本更像根据玩家历史实时生成。

但 AI 只能在四个固定物件范围内生成状态描述。

## 8.2 固定物件

AI 只能描述：

```text
notice_board
clock
broadcast_light
exit_gate
```

不能新增：

```text
乘客；
列车员；
车厢；
站外；
怪物；
隐藏房间；
新门；
新屏幕。
```

## 8.3 示例

输入：

```text
dominant_trait = control
anomaly = 3
last_choice = 尝试改写目的地
clicked_interactables = [notice_board, exit_gate]
```

AI 生成：

```text
出口门状态：许可生成中。
目的地字段曾被用户干预，门缝保持未关闭。
```

## 8.4 价值

玩家会感觉：

```text
设备不是单纯按轮次变化；
设备在根据我一路行为改变描述。
```

这强化"车站空间反馈玩家选择"的长板。

## 8.5 控制

```text
每个设备文本 1–3 行；
只能提到该设备和允许对象；
不能改变主状态；
不能暗示新路线；
失败 fallback 到 JSON texts_by_stage。
```

# 9. v0.3 需求 4：受限自由询问 / 公告屏问句实验

## 9.1 目标

尝试非常小规模的自由输入，但只在一个受限入口中出现。

入口建议：

```text
电子公告屏：输入一条询问
```

或者：

```text
向系统提交一个短句
```

## 9.2 限制

```text
每局最多一次；
只能在第二轮或第三轮后触发；
输入长度限制 20～40 字；
不作为主线必需；
不影响结局算法；
不开放给完整对话；
不能让玩家无限聊；
不能让 AI 生成新地图 / 新角色 / 新结局。
```

## 9.3 AI 处理方式

玩家输入不直接进入剧情。

流程：

```text
玩家输入一句话
→ 本地 / AI 分类为 doubt / control / obedience / observe / invalid
→ 根据分类更新一个轻微 flag 或文本反馈
→ AI 生成公告屏回应
→ 主线继续原结构
```

## 9.4 示例

玩家输入：

```text
为什么这里没有目的地？
```

系统分类：

```text
intent = doubt
```

公告屏回应：

```text
解释请求已接收。
目的地字段将在最终判断后显示。
```

## 9.5 价值

这是 v0.3 最接近 AI 原生体验的点。

玩家会感觉：

```text
我真的向系统说了一句话；
系统理解了我这句话的意图；
但游戏仍然没有失控。
```

## 9.6 风险

这是 v0.3 风险最高的需求。

可能问题：

```text
玩家乱输；
玩家破坏世界观；
AI 回答越界；
AI 变成长对话；
输入分类错误；
等待延迟；
玩家期待完全自由但实际不自由。
```

## 9.7 控制

```text
明确界面文案：提交一条校准询问，不是自由聊天；
输入长度限制；
每局最多一次；
AI 回复 1–3 行；
必须经过意图分类；
失败 fallback；
非法输入返回系统拒绝；
不改变主线结构。
```

## 9.8 是否必做

该需求建议作为 v0.3 可选核心实验。

如果 v0.2 的 AI 选项改写效果很好，可以在 v0.3 尝试。

如果 v0.2 的 AI 介入还不稳定，v0.3 应先做选项生成和设备状态生成，不急着做自由询问。

# 10. v0.3 需求 5：AI 日志、调试与失败回放系统

## 10.1 目标

AI 功能越多，越需要可调试。

v0.3 应加入开发者可见的 AI 调试信息。

## 10.2 内容

Debug Overlay 可显示：

```text
session_id
request_id
mode
dominant_trait
anomaly
last_choice_label
AI 是否启用
是否使用 fallback
最近一次 AI 输出摘要
最近一次校验失败原因
```

日志文件可记录：

```text
AI 请求状态包；
AI 原始输出；
本地校验结果；
fallback 原因；
最终显示文本。
```

## 10.3 价值

该功能对玩家不可见，但对开发极其重要。

它能解决：

```text
AI 幻觉难排查；
上下文污染难发现；
fallback 是否触发不清楚；
API 延迟和失败难复现；
用户试玩反馈难定位。
```

## 10.4 约束

```text
Debug Overlay 默认隐藏；
不要把 API key 写入日志；
不要记录隐私信息；
玩家版本可关闭日志；
日志不要无限增长。
```

# 11. v0.3 推荐实施顺序

推荐顺序：

```text
v0.3-1：AI Context Packet 标准化
v0.3-2：AI 选项文本生成，意图槽固定
v0.3-3：AI 设备状态描述生成，物件固定
v0.3-4：AI 日志与 Debug Overlay
v0.3-5：受限自由询问实验
v0.3-6：完整试玩与风险复盘
```

如果工作量必须严格控制，可以把 v0.3 缩成：

```text
必做：
1. AI Context Packet
2. AI 选项文本生成
3. AI 设备状态描述生成
4. AI Debug / fallback 日志

选做：
5. 受限自由询问
```

## 12. v0.3 最小可行版本

v0.3 最小可行版本可以是：

```text
三轮结构不变；
每轮 A/B/C/D 选项文本由 AI 在固定意图槽内生成；
四个设备调查文本可由 AI 在固定物件范围内生成；
所有 AI 输出本地校验；
失败 fallback 到 JSON；
Debug Overlay 能看到 AI 请求和 fallback 状态。
```

该版本已经比 v0.2 更 AI 原生，但工作量仍然可控。

## 13. v0.3 不做内容

v0.3 仍然不做：

```text
完全自由输入；
无限聊天；
AI 决定结局；
AI 生成新剧情树；
AI 新增地图和角色；
多 NPC；
第四结局；
第四轮主线；
复杂动态音乐；
商业发布版本。
```

## 14. v0.3 成功信号

如果玩家说出以下反馈，说明方向成立：

```text
"这次选项像是根据我刚才做的事生成的。"
"我问公告屏的问题好像真的被理解了。"
"每次设备回应都不太一样，但又没有跑题。"
"我感觉 AI 在参与，但游戏没有失控。"
"我想再玩一次，看系统会怎么重新生成选项。"
```

## 15. v0.3 失败信号

如果玩家说出以下反馈，需要回退或收缩：

```text
"AI 回复像废话。"
"AI 说了游戏里没有的东西。"
"我以为能自由对话，但其实不行。"
"等太久了。"
"选项变得太长，不想读。"
"系统解释得太多，没神秘感。"
"我不知道哪些是 AI 生成，哪些是正常游戏内容。"
```

## 16. v0.3 最终判断

v0.3 不应追求"完全 AI 游戏"。

v0.3 应追求：

```text
受限 AI 互动叙事系统。
```

核心是：

```text
结构由游戏控制；
表达由 AI 参与；
边界由本地校验；
失败由 Mock fallback；
玩家感受到 AI 介入，但游戏不失控。
```

如果 v0.3 能做到这一点，就已经是对 v0.2 长板的明显加强。
