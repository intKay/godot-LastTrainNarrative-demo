# 《叙事校准程序 / 末班车站》项目总览

## 一句话概念

玩家进入一个名为"叙事校准程序"的系统，通过几轮选择生成一段故事。系统最终将玩家导入"末班车站"场景。玩家以为自己在选择故事走向，但逐渐发现：车站正在记录、解释并利用自己的选择偏好。

## 项目类型

- 极简 2D UI 互动叙事游戏
- AI 原生叙事原型
- Godot 4.x / GDScript / Control UI
- 第一版不接真实 AI API，使用 MockAI / 预制 JSON 文本

## 核心体验

玩家不是单纯阅读文本，而是在一个可见的叙事空间中做选择。每次选择都会影响文本、系统状态、车站元素或结局倾向。玩家逐渐意识到：这个系统不是在生成故事，而是在观察玩家如何选择故事。

## 当前项目状态

- **v0.1 完整原型** — 已完成闭环
- **当前目标** — v0.2 增强版原型（5～8 分钟，可外部试玩）
- **技术路线** — Godot 4.x + GDScript + Control UI + JSON 数据驱动 + Mock AI

## v0.1 目标（已完成）

做一个 3～5 分钟的本地可运行低保真原型，验证以下核心命题：

> 玩家选择不仅改变文字，也改变可见的叙事空间；系统逐渐从玩家选择中识别出偏好，形成结局判断，并反过来影响故事。

### v0.1 包含

1. "叙事校准程序"开场界面
2. **三个**校准问题
3. 一个"末班车站"主界面
4. **三轮**车站主线选择
5. **四个**调查元素：电子公告屏、时钟、广播灯、出口门
6. 简单状态系统：怀疑、控制、顺从、异常值
7. **三个**低保真结局：顺从结局、怀疑结局、控制结局
8. 基础视觉反馈：按钮禁用、广播灯状态变化、公告屏残影

### v0.1 不包含

1. 自由文本输入
2. 真实 AI API 接入
3. 多 NPC 对话
4. 战斗系统
5. 背包系统
6. 复杂谜题和道具组合
7. 复杂 2D 角色移动
8. 动态 AI 音乐
9. Web / 手机端适配
10. 多场景长篇剧情
11. 复杂美术、复杂动画、复杂 Shader
12. 联网功能
13. 超过 3 轮车站选择

## v0.2 目标

在保留 v0.1 主线结构基础上，打磨成 5-8 分钟可外部试玩版本：

1. 系统待处理项与主交互高亮（玩家不迷路）
2. 车站空间反馈增强（每轮一个主反馈物件）
3. 系统生成式入场与低保真几何背景
4. 低保真设备按钮视觉化
5. 系统锚点音效与低频环境音
6. AI 动态引导与受限选项改写

## 成功标准

v0.1 如果满足以下条件，即视为成功：

1. 玩家能在 3～5 分钟内完成一次完整体验
2. 玩家知道自己在通过选择推进故事
3. 三问校准让玩家感到故事是"生成"而非"固定的"
4. 三轮选择逐次升级，玩家能察觉车站变化
5. 玩家能通过调查发现额外线索
6. 结局与玩家的选择模式一致，不突然说教
7. 玩家愿意重玩看另一个结局
8. 即使没有真实 AI API，玩法闭环也成立
9. 玩家试玩后能说出："我感觉这个系统在观察我的选择。"

## 当前核心风险

最高风险不是技术，而是文本质量和反馈节奏。这个项目的技术本质是 JSON 数据 + 状态机 + UI 更新；真正决定体验的是每句话是否短、冷、准、有信息量，以及每次选择是否真的产生反馈。
