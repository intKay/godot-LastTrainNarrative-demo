# 《叙事校准程序 / 末班车站》v0.1 项目总览

## 一句话概念

玩家进入一个名为“叙事校准程序”的系统，通过几轮选择生成一段故事。系统最终将玩家导入“末班车站”场景。玩家以为自己在选择故事走向，但逐渐发现：车站正在记录、解释并利用自己的选择偏好。

## 项目类型

- 极简 2D UI 互动叙事游戏
- AI 原生叙事原型
- Godot 4.x / GDScript / Control UI
- 第一版不接真实 AI API，使用 MockAI / 预制 JSON 文本

## 核心体验

玩家不是单纯阅读文本，而是在一个可见的叙事空间中做选择。每次选择都会影响文本、系统状态、车站元素或结局倾向。玩家逐渐意识到：这个系统不是在生成故事，而是在观察玩家如何选择故事。

## v0.1 目标

做一个 1 分钟的本地可运行 Demo，验证以下核心命题：

> 玩家选择不仅改变文字，也改变可见的叙事空间；系统逐渐从玩家选择中识别出偏好，并反过来影响故事。

## v0.1 包含

1. “叙事校准程序”开场界面
2. 一个校准问题
3. 一个“末班车站”主界面
4. 第一轮主线选择
5. 公告牌调查元素
6. 简单状态系统：怀疑、控制、顺从、异常值
7. 基础 UI、视觉反馈

## v0.1 不包含

1. 自由文本输入
2. 真实 AI API 接入
3. 多 NPC 对话
4. 战斗系统
5. 背包系统
6. 复杂谜题和道具组合
7. 复杂 2D 角色移动
8. 动态 AI 音乐
9. Web / 手机端适配
10. 多场景长篇剧情

## 成功标准

v0.1 如果满足以下条件，即视为成功：

1. 玩家能在 1 分钟内完成一次体验
2. 玩家知道自己在通过选择推进故事
3. 玩家能看到车站元素随选择发生变化
4. 玩家逐渐意识到系统正在记录自己
5. 玩家能通过调查发现额外线索
6. 即使没有真实 AI API，玩法闭环也成立
7. 玩家试玩后能说出：“我感觉这个系统在观察我的选择。”

## 当前核心风险

最高风险不是技术，而是文本质量和反馈节奏。这个项目的技术本质是 JSON 数据 + 状态机 + UI 更新；真正决定体验的是每句话是否短、冷、准、有信息量，以及每次选择是否真的产生反馈。
